## Обзор

**Typr** — это легковесное приложение для голосового ввода (speech-to-text), работающее из системного трея. Зажмите горячую клавишу для записи голоса, отпустите её для транскрипции — и распознанный текст автоматически вставится в любое активное текстовое поле. Поддерживается работа как с официальным OpenAI Whisper API, так и с любым совместимым локальным эндпоинтом.

**Ключевые особенности:**
- 🎤 **Push-to-talk** — удерживайте хоткей для записи, отпустите для транскрипции и вставки.
- ⌨️ **Вставка в любом месте** — текст вставляется в активное окно любого приложения.
- 🌐 **Независимость от раскладки** — корректный Unicode-ввод через clipboard backend.
- 🐧 **Linux-first** — поддержка Wayland и X11 через `evdev`/`uinput`.
- 🔌 **Hotplug** — автообнаружение новых клавиатур во время работы.
- 🏠 **Локальные endpoint'ы** — совместимо с OpenAI API и локальными STT-серверами (включая `parakeet-tdt`).

## Возможности

### Основной функционал
- **Запись по нажатию (Push-to-Talk)** — удерживайте клавишу для записи, отпустите для завершения и вставки.
- **Универсальная вставка текста** — мгновенная раскладочно-независимая вставка текста с помощью виртуального устройства ввода уровня ядра.
- **Буфер обмена Linux** — перед вставкой текущий текст сохраняется и восстанавливается
  после задержки (по умолчанию 3 секунды), только если текущая строка совпадает со
  вставленной. Это best effort, а не атомарная защита от одновременного копирования.
- **Интеграция с треем** — работа в фоновом режиме с цветовыми индикаторами статуса приложения (запись, отправка, ошибка).
- **Запись кликом мыши** — альтернативный режим: левый клик по иконке в трее для старта записи, повторный клик для остановки.

### Гибкость настройки
- **Пользовательские API эндпоинты** — используйте OpenAI, локальные Whisper-сервера, **Parakeet** или **GigaSTT**.
- **Динамический поиск моделей** — кнопка «Fetch» в настройках запрашивает список доступных моделей с вашего эндпоинта.
- **Настраиваемые горячие клавиши** — один chord в формате PortableText:
  Ctrl/Alt/Shift/Meta с A–Z, 0–9, F1–F12, Space, Enter, Esc, Tab, Backspace,
  Delete/Insert, Home/End, PgUp/PgDown или стрелками. Multi-chord и
  неподдерживаемые клавиши отвергаются backend без смены действующего shortcut.
- **История транскрипций** — сохранение истории записей локально с удобным поиском, копированием и удалением записей.

### Технические детали
- **Поддержка Wayland и X11** — работа через подсистему `evdev` не зависит от используемого композитора.
- **Автоматическая настройка прав** — установщик сам создает правила `udev` для `/dev/uinput` и добавляет пользователя в группу `input` для работы без root-прав.
- **Управляемые сетевые тайм-ауты** — подключение ограничено 10 секундами, а локальный GigaSTT получает до 120 секунд на CPU inference.
- **Адаптивный установщик** — выбирает только нужный clipboard package (`wl-clipboard` для Wayland, `xclip`/`xsel` для X11), а не устанавливает все сразу.
- **Preflight-проверка зависимостей** — перед установкой показывает полный список отсутствующих пакетов и запрашивает одно подтверждение.
- **Локализация скриптов** — сообщения в `install.sh` и `uninstall.sh` на русском при `ru`-локали консоли, иначе на английском.

## Совместимость

Этапы 1–5 Windows реализованы: persistence, PTT, async injection/audio, Settings
и миграция аудио на sounddevice. Реализован автономный per-user установщик для Windows 11 x64
на базе офлайн-архива с portable CPython 3.15.2 и локальным STT в Docker (Parakeet/GigaSTT).
Автоматизация и изолированная сборка пакета проверены; натурный desktop smoke проведен в
изолированном harness (gate 8 находится в статусе PARTIAL / OPEN). Поддержка и релизная
квалификация Python/установщика пока не приняты: native gates обеих ОС и релизная
квалификация остаются в статусе OPEN до независимого review и сквозной натурной приемки.
Оставшиеся этапы и открытые Linux/Windows gates — в
[плане Windows](docs/WINDOWS_IMPLEMENTATION_PLAN.md).

Приложение протестировано только на системе разработчика (**Manjaro Linux**). На остальных дистрибутивах Linux оно также должно работать.

Совместимость с платформами:

*   **Дистрибутивы:**
    *   **Arch-based** (Arch Linux, Manjaro, CachyOS, EndeavourOS и др.)
    *   **Debian-based** (Ubuntu, Debian, Linux Mint, Pop!_OS, Zorin OS и др.)
    *   **Fedora-based** (Fedora Workstation, Silverblue и др.)
*   **Окружения рабочего стола (Desktop Environments):**
    *   **KDE Plasma, XFCE, Cinnamon, MATE, LXQt, LXDE, Budgie** — работают из коробки, значок приложения отображается в системном трее.
    *   **GNOME** (окружение по умолчанию в Ubuntu/Fedora) — поддерживается, но требует установки расширения GNOME Shell [AppIndicator and KStatusNotifierItem Support](https://extensions.gnome.org/extension/615/appindicator-support/) для отображения иконки настроек в трее.
    *   **Оконные менеджеры** (Sway, Hyprland, i3, AwesomeWM, Openbox и др.) — поддерживаются, но требуют наличия запущенного статус-бара с системным треем (например, `waybar`, `polybar`, `tint2`).

## Установка

### Windows 11 x64: Автономный установщик (без предустановленного Python)

Для Windows 11 x64 доступен per-user установщик в виде автономного ZIP-пакета, формируемого сборочным скриптом `scripts/windows/Build-Payload.ps1` (пакет собирается локально, готовый релизный архив пока не публикуется).

Пакет включает переносимый runtime CPython 3.15.2 и все библиотеки Typr, поэтому предустановленный Python в системе не требуется. Docker Desktop и модели STT в архив не встроены: первоначальная настройка локального бэкенда требует интернет-соединения, загрузки нескольких гигабайт и явных интерактивных подтверждений.

**Порядок установки и особенности:**
- Распакуйте сформированный архив и перейдите в подпапку `Typr\`. Запустите `Install.bat`.
- Запустите `Install.bat` от имени обычного пользователя. Запуск с правами Администратора заблокирован для изоляции профиля.
- Приложение устанавливается в `%LOCALAPPDATA%\Programs\Typr`, настройки и история — в `%LOCALAPPDATA%\Typr`.
- Установщик создает ярлыки в меню «Пуск» (`Typr`, `Uninstall Typr`) и опционально предлагает добавить ярлык в папку «Автозагрузка» (`Startup`). Ярлык автозапуска запускает только само приложение Typr при входе в систему; для контейнеров STT действует политика `--restart no`, и скрытого автозапуска Docker нет.
- Для локального STT предлагаются Parakeet (сборка CPU-образа из закрепленного архива коммита `06464cd06a0f75426ce46e94c2d04ee7e26f48c0`, хэш `fa58716020a9a95d4b6695f6b0a5466f064d1b3719dd6db071f058fc3ffbbc90`), GigaSTT (канонический образ по закрепленному дайджесту `ghcr.io/ekhodzitsky/gigastt@sha256:ac7f7ccb7d5b9628d9e16cc361f29e61beedd8e1df8b0927b4a17921b7ec2f35`), оба либо пропуск (Skip).
- При отсутствии Docker Desktop установщик предлагает скачать официальный инсталлятор, проверяет цифровую подпись (`Docker Inc`, `Valid`) и запускает установку с подтверждением UAC. После запуска Docker Desktop в режиме Linux-контейнеров повторный запуск `Install.bat` продолжает настройку STT.
- Контейнеры привязываются строго к loopback (`127.0.0.1:5092` / `127.0.0.1:9876`), используют изолированные тома моделей и метки `io.typr.*`. Чужие ресурсы Docker не перехватываются.
- При чистой установке с STT создается начальный `config.json` с локальным эндпоинтом; уже существующий конфигурационный файл сохраняется без изменений.
- Автоматический запуск Typr после установки не выполняется — запустите приложение вручную из меню «Пуск».

**Проверка и удаление (из подпапки `Typr\`):**
- Read-only проверка состояния без изменений и загрузок: `.\Install.bat -Check -STT Parakeet` (допустимы `Parakeet`, `GigaSTT`, `Both`, `Skip`).
- Безопасное удаление: `Uninstall.bat` удаляет файлы программы и ярлыки, сохраняя историю, настройки, Docker и модели.
- Полная очистка моделей: `.\Install.bat -Uninstall -RemoveModels` (требует подтверждения и предварительной остановки контейнеров Typr).

Релизная квалификация установщика и CPython 3.15.2 остается в статусе **OPEN**, нативный gate 8 — **PARTIAL / OPEN** (не заявляется как готовый PASS до сквозной натурной приемки на чистой ОС Windows 11 x64).

### Windows: Ручная установка в venv (альтернатива для разработчиков)

Windows 11 x64 требует готовые wheels PyQt6, sounddevice 0.5.6 и cffi >=2.1.1,<3.
На существующем CPython 3.15.2 x64 выполнены изолированная сборка, binary-only
загрузка полного графа зависимостей, чистая установка wheel с настоящими зависимостями
и успешный `pip check`. Импорты установленного пакета из Unicode+spaces cwd прошли
без загрузки sounddevice/PortAudio. Это проверка во внешнем Temp venv, не установка
в рабочую `.venv` и не запуск приложения; native audio/GUI и полная релизная
квалификация Python остаются открыты. Подробные результаты — в
[этапе 5 плана Windows](docs/WINDOWS_IMPLEMENTATION_PLAN.md#этап-5--миграция-аудио-подсистемы-на-sounddevice-portaudio-lifecycle-metadata-и-clean-install-gates).
Ниже общая инструкция PowerShell для пользователя, а не команды выполненного smoke:

```powershell
& "C:\path\to\python.exe" -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install "C:\path\to\typr-0.4.0-py3-none-any.whl"
& ".\.venv\Scripts\python.exe" -m pip check
& ".\.venv\Scripts\typr-gui.exe"
# Диагностический запуск с консолью:
& ".\.venv\Scripts\python.exe" -m typr
```

`typr-gui` — consoleless entrypoint, `typr` — консольный. Для проверки Unicode cwd
запустите launcher по абсолютному пути из заранее созданного каталога с Unicode
и пробелами, например `C:\Users\User\Проверка Typr`. Запуск не должен зависеть от cwd.
Не запускайте второй экземпляр: системного mutex пока нет. GUI/hardware smoke требует
отдельного разрешения; эти команды здесь не выполнялись. Данные Windows хранятся в
`%LOCALAPPDATA%\Typr`; Linux shell-установщик на Windows не нужен.

Settings асинхронно обновляет устройства и проверяет выбранный микрофон. Закрытие
окна отменяет тест и результаты. Выход ждёт фактического освобождения аудио, сохраняя
отзывчивость Qt. Cancel hotkey не реализован и скрыт. Windows Settings объясняет
Ctrl+V, сохранение текста без restore/clear и ограничения elevated/UAC; Linux
сохраняет прежнее clipboard-поведение.

### Linux: Быстрая установка

Следующий установщик предназначен только для Linux.

Запустите универсальный установщик. Он:
- определит дистрибутив, DE/WM и тип сессии (Wayland/X11);
- выполнит полную preflight-проверку зависимостей;
- покажет список отсутствующих пакетов и попросит одно подтверждение;
- запросит `sudo` только перед реальной установкой;
- предложит выбрать Parakeet, GigaSTT, оба локальных STT-контейнера или пропустить этот шаг;
- настроит Python venv с `pytest` и `ruff`, desktop entries и `udev`-правила.

Запускайте скрипт **от обычного пользователя, без `sudo`**: запуск от root запрещён.
Выбор STT выполняется первым, но clone/build/start начинаются только после OS/desktop
preflight и подтверждения всех недостающих пакетов. Для локального STT устанавливается
Docker (Arch: `docker`, Debian/Ubuntu: `docker.io`, Fedora: `moby-engine` и `docker-cli`),
если для стандартного локального endpoint отсутствует Docker service unit; наличие одного
CLI не считается установленным engine. Git нужен только для Parakeet. Работающий
rootless/custom **локальный unix endpoint** используется без изменения его настроек
и без навязывания системного engine. Для стандартного локального daemon скрипт
обеспечивает active + enabled через `systemctl enable --now docker.service` с согласия
пользователя (уже active + enabled не требует повторного sudo) и проверяет `docker info`.
Установщик явно **не изменяет** членство пользователя в группе `docker` (поскольку
доступ к сокету Docker фактически равносилен root-правам). При отсутствии прямого доступа
к Docker daemon от текущего пользователя установщик выполняет необходимые команды
управления контейнерами через fallback `sudo docker` (с запросом подтверждения).
Пользователь может управлять доступом к Docker самостоятельно в соответствии со своей
политикой безопасности; скрипт не выполняет автоматическое добавление в группы.
Удалённые TCP/SSH endpoints отклоняются даже при доступном daemon: loopback-порты STT
должны находиться на компьютере Typr. `DOCKER_CONTEXT` имеет приоритет над `DOCKER_HOST`;
dry-run читает metadata выбранного context без запуска Docker. Недоступный custom unix
endpoint или отсутствие работающего systemd требуют ручной подготовки Docker;
установщик сообщает ошибку, а не успешную установку.
Простой default endpoint и `DOCKER_HOST` определяются без Python. Если Python ещё
отсутствует, разбор JSON metadata context откладывается до установки зависимостей;
dry-run сообщает об этом и всё равно показывает полный список missing packages
(engine учитывается консервативно). До запуска Docker endpoint проверяется повторно.
Все Docker-команды закреплены на проверенном `--host` с очищенными `DOCKER_CONTEXT`
и `DOCKER_HOST`, включая первоначальный `info`: переменные окружения не могут
переключить backend на непроверенный daemon.

После установки Python-пакетов выполняются `pip check` и реальные импорты runtime
зависимостей. Несовместимая с выбранным `python3` существующая `.venv` не удаляется:
установщик предлагает пересоздать её вручную. GUI из установщика не запускается:
откройте Typr из меню приложений после завершения, при новых группах сначала выйдите
из сессии и войдите снова. Автозапуск трея при следующем входе сохраняется.

```bash
# Клонируйте репозиторий
git clone https://github.com/smalever/typr.git
cd typr

# Запустите интерактивный установщик
./install.sh
```

Проверка без изменений в системе:
```bash
./install.sh --dry-run
```

`--check` работает как алиас `--dry-run`.
Оба режима показывают полный список missing packages и план сервисов/прав устройств,
не выполняя `sudo`, Docker-команды, clone, pip или запись файлов.

### Опциональный локальный STT

В начале установки скрипт предлагает выбрать локальный STT-сервер:

1. **Parakeet TDT 0.6B v3 INT8** — быстрый CPU-сервер с автоматическим
   определением 25 языков. Это вариант по умолчанию для Typr.
2. **GigaSTT с GigaAM v3 RNNT INT8** — компактный CPU-сервер,
   специализированный для точного распознавания русской речи.
3. Оба контейнера одновременно.
4. Пропустить установку локального STT.

Для Parakeet установщик:
- использует каталог `~/docker/parakeet-tdt`;
- если каталога нет, автоматически клонирует репозиторий  
  `https://github.com/groxaxo/parakeet-tdt-0.6b-v3-fastapi-openai`;
- собирает официальный `Dockerfile.cpu` и запускает отдельный CPU-контейнер
  `parakeet-tdt` с restart policy `unless-stopped`;
- предзагружает модель `parakeet-tdt-0.6b-v3` при старте контейнера и держит её
  в памяти, пока пользователь не выберет другую модель;
- хранит скачанные модели в `~/docker/parakeet-tdt/models`;
- публикует API только на loopback-адресе `127.0.0.1:5092`, без доступа из локальной сети;
- при необходимости запрашивает запуск через `sudo`.
- ждёт `/healthz` не более 600 секунд (с ограниченным timeout HTTP-запросов),
  проверяет состояние контейнера и при ошибке показывает последние 50 строк логов.
  `/v1/models` не используется для readiness Parakeet.
- перед объявлением успеха проверяет `/health`: выбранная default model должна быть
  `parakeet-tdt-0.6b-v3`, находиться в `loaded` и использовать CPU INT8 runtime.
  При повторной установке контейнер с label `io.typr.stt=parakeet` пересоздаётся,
  если изменились image ID или параметры CPU/default model/batching; прежний bind mount
  `models` сохраняется. При неизвестном mount или несовпадающем чужом контейнере
  установка останавливается без удаления контейнера.

Base URL Parakeet: `http://127.0.0.1:5092/v1`.

Кнопка **Fetch** использует стандартные `/models` и `/audio/models`. Для распознанного
Parakeet optimized API она получает только уже загруженные модели через `/health`,
а не весь каталог поддерживаемых профилей. **Проверить соединение** для этого API
проверяет готовность default model. У неизвестного endpoint ошибка 404 не подменяется
встроенным списком моделей. Deployment prefix в Base URL сохраняется.

Для GigaSTT установщик:
- использует официальный CPU image `ghcr.io/ekhodzitsky/gigastt:latest`;
- перед каждым запуском выполняет `docker pull` и безопасно пересоздаёт только принадлежащий Typr контейнер, если image обновился;
- запускает отдельный контейнер `gigastt` с restart policy `unless-stopped`;
- явно фиксирует `GIGASTT_MODEL_VARIANT=rnnt` и `--pool-size 1`;
- сохраняет автоматически загруженную GigaAM v3 RNNT INT8 в Docker volume
  `gigastt-models`;
- внутри контейнера хранит модель по пути `/home/gigastt/.gigastt/models`, а на
  хосте Docker хранит содержимое в volume `gigastt-models`;
- публикует API только на loopback-адресе `127.0.0.1:9876`, без доступа из локальной сети;
- ждёт готовности `/ready`, а не только открытия порта; при timeout показывает последние 50 строк `docker logs gigastt`;
- выводит Base URL `http://127.0.0.1:9876/v1` и модель `gigaam-v3-rnnt` после запуска.

Typr поддерживает одиночный объект модели, который GigaSTT возвращает из `/v1/models`,
поэтому кнопка **Fetch** показывает `gigaam-v3-rnnt` в списке моделей.

При повторной установке существующие контейнеры запускаются снова, а сохраненные модели
используются без повторной загрузки. Безопасно обновляется только контейнер с label
`io.typr.stt=gigastt`; если имя `gigastt` занято другим контейнером, установщик завершает
STT-шаг с ошибкой и не изменяет его.
Parakeet с конфликтующим image также не удаляется; пересоздание из-за неверного port
binding разрешено только с label `io.typr.stt=parakeet`. Порты остаются loopback-only.

Если при первой установке выбран только GigaSTT и config ещё отсутствует, установщик
создаёт его с Base URL `http://127.0.0.1:9876/v1` и моделью `gigaam-v3-rnnt`.
При выборе Parakeet или обоих backend'ов сохраняется Parakeet default. Существующий
`~/.config/typr/config.json` никогда не перезаписывается установщиком.

> [!NOTE]
> После первой установки может потребоваться выйти из системы (Log Out) и зайти снова, чтобы применились права группы `input`.

## Использование

1. **Запуск** — запустите Typr из меню ваших приложений или через терминал с помощью команды `./.venv/bin/typr` (находясь в папке проекта).
2. **Настройка** — нажмите правой кнопкой мыши по иконке в трее → **Settings**.
   - По умолчанию выбран `Base URL`: `http://127.0.0.1:5092/v1`; API-ключ для локального Parakeet не требуется.
   - По умолчанию выбрана модель `parakeet-tdt-0.6b-v3`.
   - Для другого сервера измените `Base URL`, при необходимости введите API-ключ, затем во вкладке **General** нажмите **Fetch** и выберите модель.
   - Для GigaSTT поля **Language** и **Context** отключаются: его OpenAI endpoint принимает, но не применяет их к GigaAM. Для Parakeet и других OpenAI-compatible API поля остаются доступны.
3. **Запись** — **зажмите** сочетание клавиш `Ctrl+Alt+Z` (по умолчанию) и говорите.
4. **Вставка** — **отпустите** клавиши. Текст распознается и вставится в текстовое поле, где стоял фокус.

### Политика буфера обмена Windows (реализованный backend, runtime еще не принят)

Typr ожидает отпускания Ctrl/Shift/Alt/Win и клавиши V до 2 секунд, помещает распознанный текст
в буфер обмена и отправляет Ctrl+V. Текст **остается в буфере**, как после Copy:
Typr никогда не очищает и не восстанавливает его, включая ошибку вставки и выход.
Позднее внешнее копирование не перезаписывается cleanup. Если эти клавиши не отпущены,
операция завершается ошибкой без изменения буфера и без принудительного keyup.
Успех означает отправку событий, не подтверждение вставки целевым приложением.
Внешнее копирование между публикацией и Ctrl+V может изменить результат вставки.
Elevated приложения и secure desktop/UAC не поддерживаются, ограничения UIPI не обходятся.
Транскрипция сохраняется в истории (если включена) независимо от ошибки вставки.
Настройки задержки уведомления не гарантируют restore на Windows; отдельной настройки
restore нет. Подсказка в Settings и адаптация i18n реализованы на этапе 4.

На Linux clipboard helpers работают без отделения в фон (`wl-copy --foreground`,
`xclip -quiet`, `xsel --nodetach`), включая восстановленный текст. При выходе Typr
асинхронно дожидается завершения injection worker и освобождения helpers/uinput,
сохраняя отзывчивость Qt. Принудительного timeout выхода нет; непрерываемый системный
вызов устройства может задержать завершение процесса.

## Настройка

Конфигурационный файл хранится по пути: `~/.config/typr/config.json`

Новая конфигурация создаётся со следующими основными значениями по умолчанию:

```json
{
  "api_base_url": "http://127.0.0.1:5092/v1",
  "transcription": {
    "model": "parakeet-tdt-0.6b-v3"
  },
  "hotkeys": {
    "push_to_talk": "Ctrl+Alt+Z"
  }
}
```

Уже сохранённые пользовательские настройки автоматически не перезаписываются.

### Горячие клавиши

Настройка доступна через графический интерфейс (Settings → Hotkeys) или вручную в конфигурационном файле:

```json
{
  "hotkeys": {
    "push_to_talk": "Ctrl+Alt+Z"
  }
}
```

Поддерживаемый формат: `Модификатор+Модификатор+Клавиша` (например, `Ctrl+Alt+Z`).

## Устранение неполадок

### Ошибка «No keyboard devices found» или проблемы со вставкой текста
Убедитесь, что ваш пользователь добавлен в группу `input`:
```bash
groups | grep input
```
Если группы нет, выполните:
```bash
sudo usermod -aG input $USER
```
После этого обязательно выйдите из системы и зайдите снова (или перезагрузите ПК).

### Ошибки прав доступа к `/dev/uinput`
Убедитесь, что файл `/etc/udev/rules.d/99-uinput.rules` существует и содержит строку:
```udev
KERNEL=="uinput", GROUP="input", MODE="0660"
```
Установщик `install.sh` делает это автоматически, но в некоторых системах может потребоваться ручная перезагрузка правил:
```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
```
Он также загружает модуль `uinput` через `modprobe` и проверяет устройство и права
`input:0660`. Существующие udev rules не перезаписываются: конфликтующие права требуют
ручной проверки правил. Для не встроенного в ядро модуля, если нет готовой записи
modules-load, создаётся `/etc/modules-load.d/typr-uinput.conf` с `uinput`, чтобы
устройство появлялось после перезагрузки.

После первой установки, если пользователь добавлен в группу `input`, **выйдите из
графической сессии и войдите снова**: уже запущенная сессия и её приложения не получают
новые группы автоматически. До этого глобальная горячая клавиша может не работать,
даже если STT уже готов. По умолчанию используется `Ctrl+Alt+Z`; пользовательская
комбинация, например `Ctrl+Shift+Z`, также допустима и не требует смены default.

### Зависание статуса «Transcribing...»
Typr ждёт подключение до 10 секунд. Read timeout составляет 120 секунд для локального
GigaSTT и 30 секунд для остальных endpoint'ов. Если транскрипция не завершилась,
проверьте доступность API кнопкой **Test Connection** во вкладке **API**.

## Удаление приложения

Для полной очистки системы от интеграции Typr и удаления виртуального окружения запустите деинсталлятор из папки проекта:

```bash
./uninstall.sh
```
`uninstall.sh` удаляет:
- desktop/autostart интеграцию Typr;
- локальные настройки, кэш, историю и `.venv`;
- legacy user-level `pip` install (если был).

Деинсталлятор останавливает и удаляет оба поддерживаемых контейнера, `parakeet-tdt` и
`gigastt`, если они существуют. Затем он отдельно предлагает удалить сохраненные модели:
каталог `~/docker/parakeet-tdt` и Docker volume `gigastt-models`. По умолчанию модели
сохраняются для быстрой переустановки. Если контейнер безопасно удалить не удалось,
связанные с ним данные не удаляются.

Примечание: папка самого репозитория Typr не удаляется.
Деинсталлятор отдельно запрашивает подтверждение очистки системной настройки `uinput`.
`/etc/modules-load.d/typr-uinput.conf` удаляется только при точном содержимом `uinput`
с одним завершающим переводом строки, как создаёт установщик. Изменённые файлы и
символические ссылки сохраняются; другие modules-load entries не затрагиваются.

## Стек технологий

- **Язык программирования**: Python 3.10+
- **Интерфейс (GUI)**: PyQt6
- **Аудио**: sounddevice 0.5.6 / PortAudio >=19.6.0,<20; blocking RawInputStream
  без NumPy. Linux требует системную PortAudio (`libportaudio2`); Windows wheel
  содержит DLL, но системная библиотека может иметь приоритет. Ошибка финального
  освобождения backend отключает аудио до перезапуска Typr; native audio smoke
  на Windows/Linux остается непроверенным.
- **Низкоуровневый ввод**: evdev / uinput (прямой доступ к устройствам ввода Linux)
- **Сетевой клиент**: httpx
- **Clipboard backends**: `wl-clipboard` (Wayland), `xclip`/`xsel` (X11; выбирается автоматически установщиком)

## Разработка

Карта архитектуры, developer workflow и правила синхронизации code/tests/docs находятся в [docs/README.md](docs/README.md).

Проект содержит адаптированные Kilo skills в `.kilo/skills/`:
- `typr-codebase` — навигация по runtime-компонентам и правила безопасных изменений;
- `typr-coordination` — проектное дополнение к глобальному `subagent-coordination` (оба навыка — только для основной сессии);
- `code-review` — ревизия незакоммиченных изменений с проверками и исправлениями;
- `git-commit` — безопасная подготовка локального commit после review.

Kilo загружает их через проектный `kilo.json`. После изменения skill перезагрузите project configuration или начните новую сессию.

Базовые проверки:

```bash
./.venv/bin/pip install -e '.[dev]'
./.venv/bin/pytest
./.venv/bin/ruff check tests/test_project_skills.py
bash -n install.sh uninstall.sh
```

Hardware-dependent проверка микрофона, глобального хоткея, clipboard и `/dev/uinput` выполняется вручную в видимой Linux desktop session.
