# Typr Agent Contract

- Перед нетривиальными изменениями, проектированием или ревью загрузи skill `typr-codebase`.
- Сохраняй основной pipeline `hotkey -> audio -> transcription -> text injection` неблокирующим для Qt UI и потоков чтения устройств ввода.
- Не запускай интерактивные `install.sh` и `uninstall.sh` без явной необходимости. Для проверки установщика используй `./install.sh --dry-run` только когда окружение подходит для его preflight-проверок.
- Python-команды запускай из проектного окружения `.venv`, если оно существует. Не подменяй отсутствующую системную или desktop-зависимость заглушкой в production-коде.
- Не открывай и не публикуй пользовательский `~/.config/typr/config.json`: он может содержать API key. В tests используй временный HOME и фиктивные значения.
- Обратная совместимость внутренних API и форматов config/history не требуется: оптимальная архитектура и улучшения важнее поддержки старых API, форматов или поведения. Legacy-адаптеры, ветки совместимости и миграции ради поддержки старых версий/форматов не добавляются; старые внутренние API, форматы и поведение допустимо изменять или удалять ради улучшений (преобразование данных для новой функциональности и cleanup допустимы). Это не разрешение удалять реальные данные, скрыто сбрасывать настройки или нарушать security.
- При изменениях кода синхронизируй tests и docs по `docs/DOCUMENTATION_POLICY.md`, затем проверь `git status` и `git diff`. Не включай `.venv`, caches, logs и другие generated artifacts.
- Перед каждым commit после review и непосредственно перед staging повысь SemVer приложения через `scripts/bump_version.py` по правилам `.kilo/skills/git-commit/SKILL.md`; version bump входит в тот же commit.

## Работа С Субагентами

- Основная сессия выступает координатором, архитектором и приемщиком: сама выполняет только тривиальные действия (1–2 известных места, без исследования и изменения контрактов), а остальное делегирует после загрузки skill `subagent-coordination`.
- Архитектура, thread/clipboard semantics и системные разрешения утверждаются основной сессией, исполнение может делегироваться. Финальную приемку выполняет основная сессия.
