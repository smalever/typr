# Code Review

## Назначение

Явно делегированный ревьюер работает без правок. Тот же режим применяется при запрете пользователя и для исторического diff ветки, commit или PR без отдельного запроса на исправления.

После завершения автора для нетривиального diff, особенно потоков, clipboard и разрешений, привлекай независимого ревьюера с чистым контекстом. Для тривиальных правок документации отдельный ревьюер не нужен. Основная сессия проверяет замечания и назначает исправления отдельным этапом по `AGENTS.md`. Обычное ревью незакоммиченного рабочего дерева предусматривает исправление подтвержденных дефектов.

Перед нетривиальным review загрузи `typr-codebase`. Глобальные ограничения задает `AGENTS.md`, обязательные companions - `docs/DOCUMENTATION_POLICY.md`, команды проверок - `docs/DEVELOPMENT.md`.

## Область

Начни с:

```bash
git status --short
git diff
git diff --staged
```

Проверяй tracked, staged и содержательные untracked файлы целевой работы и их прямые связи, а не проводи тотальный аудит всего репозитория. Несвязанные изменения отмечай отдельно, но не исправляй.

## Проверка

Оцени:

1. Корректность state transitions, error recovery и cleanup.
2. Blocking I/O и thread ownership в Qt, audio, network и input paths.
3. Clipboard preservation, Unicode paste и races с пользовательским clipboard.
4. Безопасную обработку config/history, atomic persistence и защиту API key; отсутствие legacy-поддержки само по себе не дефект согласно AGENTS.md.
5. `evdev`/`uinput` permissions, installer/uninstaller safety и desktop integration.
6. Отсутствие лишней сложности, мертвого кода и legacy-адаптеров, веток совместимости или ненужных миграций ради старых версий/форматов (такие адаптеры и ветки считаются избыточными согласно AGENTS.md).
7. Локализацию новых пользовательских строк на RU/EN.
8. Позитивные, негативные и regression tests.
9. Актуальность docs по `docs/DOCUMENTATION_POLICY.md`.
10. Secrets, debug code, caches, logs и лишние generated files.

## Исправления И Проверки

Правила выбора и запуска проверок регламентируются `docs/DEVELOPMENT.md`. При обнаружении дефектов исправляй только подтвержденные проблемы в целевой связке, включая tests/docs. Не выполняй несвязанный refactor и не меняй test только ради зеленого результата.

После трех неудачных циклов исправления и проверки одной проблемы пересмотри подход: переоцени причину, сузь задачу или назначь другого исполнителя.

Blocker фиксируется, только если отсутствует безопасный следующий шаг, требуются недоступные разрешения, ресурсы или отдельное решение пользователя, либо обнаружены отсутствующий project toolchain, external API/secret, destructive operation, конфликт чужих изменений или архитектурное решение вне запроса.

## Финальная Приемка

Повторно проверь `git status --short`, `git diff` и `git diff --staged`. Убедись в полноте tests/docs, отсутствии secrets/artifacts и сообщи исправленные defects, проверки, blockers и оставшиеся несвязанные изменения.

В review-only начни с findings по severity с `file:line`; если findings нет, скажи это явно и укажи residual risks или testing gaps.
