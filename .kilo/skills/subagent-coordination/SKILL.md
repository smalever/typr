# Координация Субагентов

## Назначение

Загрузи skill перед первым делегированием в нетривиальной задаче; роли основной сессии определены в `AGENTS.md`. Субагенты выполняют поручения самостоятельно без дальнейшего делегирования.

## Роли И Подходящие Задачи

| Роль | Назначение и область |
| --- | --- |
| `explore` | Поиск без правок: карта файлов, места вызова, связанные документы, разбор логов и диагностика. |
| `mechanic` | Точная спецификация, сверки, прогоны проверок, механические правки по списку без бизнес-логики. |
| `general` | Реализация по согласованному дизайну, целевые тесты, документация, синхронизация компонентов, обычное ревью без правок. |
| `general-deep` | Задачи с высоким риском: конкурентность, границы потоков, восстановление, машины состояний, ревью без правок. |

Выбор исполнителя определяется характером задачи, без жестко заданных моделей.

## Контракт Подзадачи

Поручение должно содержать:

```text
Цель и ожидаемый результат:
Источник истины или исследовательский вопрос:
Разрешенная область чтения и записи:
Запрещенные изменения и операции:
Критерии приемки:
Проверки:
Формат отчета:
```

Для правок требуй минимальный diff; запрещай commit, revert, массовое форматирование, чтение реальных пользовательских секретов и изменение несвязанных файлов.

## Параллельная Работа

Параллельно запускай только задачи без пересечения файлов, архитектурных решений и runtime-ресурсов. Файлы `app.py`, `config.py`, `pyproject.toml`, установочные скрипты и канонические документы должны иметь одного исполнителя на этап.

Не запускай конкурентные проверки, одновременно использующие микрофон, `/dev/input`, `/dev/uinput`, clipboard или одну GUI-сессию.

## Review И Приемка

Порядок независимого ревью и исправлений — в `code-review`.

1. Проверь отчет, измененные файлы и полный diff.
2. Подтверди отсутствие выхода за область задачи и чтения секретов.
3. Сверь обязательные связанные изменения по `docs/DOCUMENTATION_POLICY.md`.
4. Ключевой результат подтверди чтением подтверждающих материалов или целевой проверкой; ее выполнение можно поручить субагенту.
5. При ошибке один раз продолжи то же поручение с точным списком оставшейся работы. Если результат не достигнут, переоцени область, уменьши задачу, смени роль, утверди решение и переделегируй нетривиальную реализацию по `AGENTS.md`.

## Stop Conditions

Субагент сообщает о блокирующем обстоятельстве при необходимости несогласованного изменения архитектуры или семантики, выхода за область записи, использования реальных config/history, привилегированной или разрушительной операции, конфликтующего desktop-ресурса либо при неразрешимом противоречии кода и контракта. Реализация согласованного архитектурного решения не является препятствием.
